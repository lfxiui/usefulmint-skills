# 上线前检查（提示词版）

把下面整段内容复制给 AI，然后按它的提问回答。

---

请帮我做一次上线前检查。我不懂代码，请用大白话说明。

要求：

1. 先确认项目根目录和项目类型，读一下现有的说明文件，不要凭猜测行动。
2. 在动手修改之前，只做只读检查，检查这些方面：
   - 密钥与隐私：有没有密钥被写进代码、被提交进仓库，或者放在浏览器能看到的位置
   - 环境配置：实际需要的配置项是否齐全，有没有把本地地址写死
   - 能否正常构建：跑一次构建，看是否报错
   - 页面与链接：主要页面能否打开，链接和图片是否有缺失
   - 手机显示：是否适配手机，文字按钮是否溢出
   - 搜索与分享：标题描述是否独立，分享卡片是否存在
   - 出错表现：操作失败时是否有能看懂的提示，有没有对外暴露的管理或调试入口
   - 收费与测试内容：是否残留测试数据和测试模式
   - 依赖安全：是否有高危漏洞
3. 检查完给我一份报告，分成：结论、必须修、建议修、已经没问题的部分、需要我自己操作的步骤。
4. 每一条都要说清：我会看到什么现象、谁会受影响、建议怎么处理。
5. 报告出来后，先不要改代码。等我确认后再逐项修，每修一类问题让我看一次结果。
6. 检查过程中不要写出密钥的具体内容。
7. 无法检查的项目要明确写"没检查到"，不要写成"通过"。
